## Where the evidence stands

DeFoG has been most useful as a search aid when the optimizer also has explicit graph constraints and saves intermediate candidates. In the LR 60 study, adding weight 0.5 to connected projection improved the best valid hard contact over projection alone in all nine available matched seed/start comparisons, counting the recovered pair once. Only three of those nine guided endpoints were valid and connected. The same series gives a much weaker case for a learned prior working by itself. With Stage 2 operators disabled, weight 0.0625 produced **zero new valid identities** across nine runs. The three valid observations were the initial sparse graphs. The corresponding teacher-off runs had the same result.

The custom structural repair loss is a genuinely competitive alternative. Without Stage 2 projection, it found new valid molecules from both fragmented starts completed in the November head-to-head. Each method won on best valid contact for one seed, and each ended connected and valid once. DeFoG found many more distinct valid candidates on seed 23. The strongest inference is about the two *completed trajectories*. Seed 42 is pending, starts reuse earlier seeds, and all these Protenix examples use one pocket and one atom count.

## What Stage 3 asks

The project description sets three tests for adding a learned molecular prior to the existing optimizer. First, establish that the checkpoint can read the actual relaxed graph. Second, query it once per update and test a moderate discrepancy penalty alongside optional Stage 2 projection. Third, look for better raw chemistry, closer agreement between relaxed and hard scores, and continued movement toward the native objective. A high contact score on fractional probabilities alone cannot answer any of these questions. [Project description, §§6.1–6.3](https://github.com/NikolajHJ/mosaic/blob/2eeeba20261633cd297ff79b15b527465ead890e/docs/project_desc.pdf)

The motivation for DeFoG is that a learned distribution can favor combinations of atom identities, bond orders and local environments seen together in molecules. A valence cap can detect overload on an atom but leaves many possible edits equally admissible. DeFoG can assign different preferences to those edits given the surrounding graph. This is a reason to test it. The checkpoint has no BRD4 pocket input here, and a high-probability proposal from it has no direct meaning as a binding prediction. Protenix supplies the pocket-specific signal.

## The state, the teacher and one optimizer update

For N = 25, atom probabilities X have shape (25, 6), with categories C, N, O, S, F, Cl. Bond probabilities E have shape (300, 5), one row per unordered pair, in the order no bond, single, double, triple, aromatic. All rows sum to one. Atom count, charge support and atom order are fixed. Protenix receives these relaxed atom choices and bond existence through its adapter. DeFoG and the graph operators see the full bond categories. Redistributing mass between single and double can therefore change teacher and valence terms while preserving the bond-existence feature of the native scorer.

The current teacher is a frozen GuacaMol DeFoG checkpoint. At update k, feed the current graph and teacher time t to the denoiser and take the predicted *clean categorical distributions* Q. This is one model forward. It predicts an endpoint distribution conditional on the graph and time. We do not integrate a flow to completion or sample a discrete repaired molecule in this path. Detach Q for the duration of the update. The target moves on the next update because the input graph changes.

For the reference probability-MSE formulation, with unit atom and bond scales:

    D_atom = sum_i ||X_i - Q_atom_i||² / N
    D_bond = sum_{i<j} ||E_ij - Q_bond_ij||² / (N(N-1)/2)
    L_k    = -Protenix_contact(G; fixed pocket and key) + w_k (D_atom + D_bond)

The categorical squared errors sum within each row. Atom and bond heads are then averaged separately so 300 bond rows do not automatically outweigh 25 atom rows. For a stopped target, the atom-prior gradient is proportional to X minus Q_atom, and likewise for bonds. There is no teacher Jacobian term. Earlier KL/logit runs use a different distance and parameterization. An identical numerical coefficient need not imply identical graph movement.

1. Construct the graph view for this step, including cooling if configured. Obtain Q from that view and freeze it. Use the same intended view for the native scorer.
2. Differentiate the combined objective with respect to the graph variables. Apply the native and teacher gradients, then restore the probability rows to the simplex.
3. If enabled, apply the chosen Stage 2 operators. Form the raw argmax by selecting the most probable element and bond category in each row. Score the hard graph with the same Protenix context and key and assess its chemistry separately.
4. Archive the best eligible hard graph and the highest-ranked distinct candidates. Continue optimization from the relaxed state. The candidate archive and detached RDKit checks do not feed a repaired winner back into the ordinary DeFoG loop.

**Three independent controls.** The learning rate scales the update. The weight w scales the discrepancy gradient relative to the native gradient. Teacher time t is the conditioning time of the pretrained flow model. It can stay fixed at 0.8 for hundreds of optimizer updates. A temperature T on the categorical probabilities controls sharpness. It is independent of t. One cooling operator uses normalized p raised to 1/T, so reducing T sharpens distinctions already present.

## What “with projection” means

All probability-space arms enforce valid probability rows. “No projection” in the experiments means Stage 2 graph operators are off. No extra step enforces chemical valence or actively joins components. For connected projection, Stage 2 adjusts probabilities against valence caps and proposes bridges between components. The reference settings reapply valence after bridging and include a fluidity floor that allows future movement. Other arms vary damping, caps, bridge strength/retry, shrinkage, application frequency and late activation. Valence-only projection has a different scientific meaning from connected projection.

A proposed bridge can lose the hard argmax after valence readjustment or at a later native update. Likewise, two plausible local bond changes can jointly disconnect a graph. The learned loss has no explicit single-component requirement. A graph can sanitize as several valid fragments, so sanitization and connectivity must be checked independently. The original 30k sparse comparison illustrates the difference unusually clearly.

## From sampled DBMol repairs to a one-query soft teacher

The early DBMol/Boltz approach continued stochastic DeFoG trajectories, filtered the resulting candidate graphs, and used selected repairs as fixed targets for the decoder while optimizing its latent variable. The short six-update integration selected two targets from eight eligible native outputs and transmitted both gradients to the latent state. All seven raw argmax states were invalid. In a later matched 25-update pilot both arms had 0/26 valid raw argmax states. At 500 planned updates, the guided arm completed but had 0/9 valid endpoint candidates, while the control stalled after 225 accepted updates. Repair proposals and raw generated molecules are different outputs. These runs showed target selection and gradients could work without demonstrating useful generation.

Moving to one query per update avoided waiting for an entire sample and allowed small continuous steps toward a probability distribution. The checkpoint required an adapter. On a bounded CPU test, native auxiliary features accepted 4/20 fractional baseline inputs. Building auxiliary features on the hard argmax while sending soft probabilities to the transformer accepted 20/20. Identical successful queries reproduced identical predictions. For ordinary tiny perturbations, the largest adapted output change was 0.0056 in maximum-cell total variation. Crossing a near tie with only 0.0002 input change produced a change of 0.499 in one output row, compared with 0.994 when the whole input was hardened. A small optimizer step often limits movement, but a single forward can still change the target sharply at a category boundary. Ten short adapted teacher-only paths preserved the initial argmax, including an overvalent control. [Compatibility probe implementation](https://github.com/NikolajHJ/mosaic/blob/2eeeba20261633cd297ff79b15b527465ead890e/experiments/learned-prior/defog-soft-teacher/probe.py). The measured results are archived in the research checkout at `experiments/learned-prior/defog-soft-teacher/RESULTS.md`.

## The LR 60 Stage 3 campaign

**Design.** 155 distinct settings × three starting graphs × seeds 17, 23 and 42 = 1,395 planned runs. Each run uses 500 updates, native weight 1, fixed Protenix-Tiny BRD4 context and a fixed model key per seed. Starts are a sparse valid tree, a dense random bond graph with the same atom probabilities, and the sparse tree with four bonds removed. Fixed teacher weights ranged from 0.015625 through 0.5 alongside a zero control. Fixed times included 0.2, 0.5, 0.8 and 0.95. The sweep also varied time and weight schedules, projection, cooling placement and gradient, teacher refresh, atom/bond contributions, target distance, and simple valence loss.

**Coverage and selection.** The original sweep completed 1,390 runs, of which 1,143 visited a valid molecule, 1,027 visited a new valid identity, and 11 ended valid. Five original arms stopped on projection checks. Their reruns and one matched treatment repeat completed. All 1,395 settings/starts/seeds therefore have at least one full trajectory. There are 1,401 attempts, including partials and the duplicate successful treatment. The sweep includes weak arms by design. Its pooled endpoint fraction is descriptive of the design, not the success probability of the selected setting.

## The November head-to-head with structural repair

The historical custom loss performs a detached, atom-preserving repair search. A connected-backbone proposal can be followed by bounded beam/progress searches. A valid repair witness supplies a fixed likelihood target. Depending on the route, edited-bond likelihood, local bond risk or component-cut risk can provide gradients when a complete witness is unavailable. An already-valid input receives zero repair loss. This makes it possible to leave a valid graph again under Protenix guidance. The repair target is never itself counted as a generated molecule.

Three methods use the same fragmented initialization per seed, 25 slots, native weight 1, LR 60, 500 updates and temperature 1. The selected DeFoG method uses w = 0.5, t = 0.8 and connected projection. The repair loss uses weight 1, with and without the same Stage 2 operators. A shared 0.0001 uniform mixture after initialization and after each probability update makes the historical log likelihood finite. The historical repair study optimized logits, while these comparison arms update probabilities. The DeFoG arm was rerun under this convention. Within each completed seed the effective initial atom/bond tensors and Protenix key matched across all three arms. Repair-only uses a separate GPU allocation on the same queue.

## What to retain, verify and compare

- **Primary candidate.** Select the highest hard Protenix score among raw argmax graphs that both sanitize in RDKit and contain a single component. Preserve the exact ordered graph and update for rescoring. Canonical SMILES identifies a molecule, but different orderings can matter for the native context. The initial state is eligible and explicitly flagged. A run without a qualifying molecule has a missing best score.
- **Generation and retention.** Report seeds finding any new valid identity, valid-state fraction, distinct valid canonical identities, valid fraction over the last 100 states, and final validity/components separately. A chain that never changes can look perfect by state count. A trajectory with hundreds of valid identities can finish disconnected. Hard scores alone obscure both cases.
- **Pairing.** Match seed, initialization arrays, scorer/context digest, model key, LR, budget and shared graph convention. For projected versus unprojected comparisons the graph operators are an intended difference. Record hardware separately if allocations differ. A re-execution with the same seed can diverge. Treat time points as correlated and group replications by seed.
- **Storage and extraction.** Each run keeps its configuration, status, summary, initial tensors, per-update states, gradients and operator receipts. Inspect top_valid.json and top_valid.npz for up to 20 ranked distinct identities. The comprehensive report contains 9,668 shortlisted records and 6,993 distinct shortlisted SMILES. For most display traces it retains every 25th update plus best and last. Use the HPC states.jsonl.gz for full-resolution trajectories.
- **Package scope.** The extracted mosaic_defog worker was checked against the historical adapter on six native test inputs with zero target mismatch. Frozen-state and student-gradient checks passed. The individual CPU teacher calls in that test took about 0.068–0.076 s excluding startup, model scoring and optimization. Scope parity claims to the tested inputs. Runtime, teacher compatibility and molecular efficacy are separate questions.

## Directions worth testing next

1. **Confirm the practical comparison.** Finish seed 42, freeze the chosen settings, then use the reserved seeds 71 and 101 before changing hyperparameters. Reuse matched native keys and initial tensors. Keep the best valid hard graph as the primary output and final valid/connected as a separate requirement. Report every seed and runtime. If one method wins primarily in a single trajectory, present it as a candidate strategy rather than a default.
2. **Locate the first lost connection.** From saved states, select a valid-to-disconnected transition and an adjacent transition that stayed connected. For a crossing edge, track its no-bond margin before the gradient step, after the step, after bridging, and after valence adjustment. Use operator receipts, replay only the missing intermediate values, and compare with repair-only on the same seed. If post-bridge valence consistently erases an essential edge, test one targeted bridge-retention change. If the native step erases it first, test a smaller late step.
3. **Find out what information the teacher contributes.** Compare refreshed versus fixed-initial versus identity targets at the selected weight, with native budget, projection and displacement measured per head. Ask whether a refreshed target yields more *new* valid hard graphs than comparable regularization alone. Inspect proposals near category ties. This is more diagnostic of learned information than testing another schedule with a different total gradient budget.
4. **Test search and retention as separate phases.** A bounded late-stage step-size decrease or an explicit archive-and-restart from the best valid state could preserve a useful graph. Compare each change against the unchanged optimizer from the same saved state. Keep final raw outputs and archived outputs in separate columns. Count any extra native evaluations so the method cannot win just by evaluating more candidates.
5. **Generalize only after the within-pocket comparison.** Repeat the selected recipe on held-out starts and a second pocket or atom count. A DiGress-style teacher or a VAE projection would be a separate model-family test. Require vocabulary and graph alignment and match scorer calls and compute. Add scaffold/fingerprint diversity and independent hard rescoring before interpreting canonical uniqueness or the contact proxy as evidence of useful design.
