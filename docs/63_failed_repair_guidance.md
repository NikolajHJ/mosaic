# Experimental guidance when bounded repair finds no valid target

**Separate authorized prototype, 18 October 2026.** Opt-in implementation and
static modularity review are complete; numerical fixtures, native coverage, runtime and
retention validation have not run. This is not production adoption and is
not wired into the running source121 chemistry continuation. Its existing
loss, ratio, checkpoint/optimizer/RNG lineage and automatic continuation are
unchanged. No existing HPC job was modified.

The prototype lives in
[`repair_progress.py`](../src/latentmol/repair_progress.py) and
[`repair_failure_guidance.py`](../src/latentmol/repair_failure_guidance.py).
It combines a separate detached search pass with explicitly limited
differentiable signals for rows that still have no complete valid target.
It does not add a learned prior/scorer, a second molecule for another scoring
branch or chemistry conversion inside autograd.

## Current zero-target behavior and saved coverage

The original teacher distinguishes accepted valid witnesses, already-valid
graphs, bounded-search censoring, unsupported input and errors. An accepted
target receives full categorical NLL. Already-valid or unsuccessful rows have
no target NLL and remain in the all-attempt denominator; already-valid is a
success, not a failed search. `rejected_or_error` aborts a successful update
rather than silently becoming an ordinary censored row. A zero direct repair
term does not imply zero total training gradient from all other objectives.

## Detached preparation and search escalation

`prepare_failure_guidance(decoded, base, spec, progress_search=...)` requires
the exact original teacher snapshot and complete per-row `RepairTargetBatch`
receipt. It checks candidate IDs, source graph/probability identities and
target/status consistency, including accepted target source-update/full-label
records against the original attempt; unknown/error statuses are rejected. Original
accepted and already-valid rows receive no new failure reference. Original
censored/unsupported rows freeze their hard atom/charge/occupied-slot labels,
bond labels, supported local caps and connected components outside autograd.

An optional `ProgressSearchConfig` starts a new bounded pass from the same
original raw graph. It is not a continuation from an unrecorded three-edit
frontier or a certified nine-edit search. Original work is not free, and the
additional preparation/revalidation wall time must be measured separately.

| Search setting | Default | Declared prototype bounds |
| --- | ---: | --- |
| `version` | `repair-progress-v1` | Explicit version required |
| `max_edits` | 6 | 1–12 |
| `checks_per_depth` | 32 | 1–4,096 across the frontier at each depth |
| `beam_width` | 4 | 1–128 retained frontier candidates |
| `probability_weight` | 1.0 | Finite, nonnegative |
| `allow_atom_edits` | False | Explicit opt-in |
| `max_atom_edits` | 1 | Optional maximum 2 |
| `atom_edit_penalty` | 3.0 | Additional cost per changed atom; at least 1 |

The default permits at most 192 additional candidate checks, plus initial
diagnosis and native confirmation work; it is not a runtime guarantee. Beam
pruning, deduplication and an exhausted frontier can reduce actual coverage.
The observed cost combines probability-aware edits with an extra atom-edit
penalty, explicitly recorded as:

```text
edit_count + probability_weight * sum(max(0, log(p_old/p_new))) + atom_edit_penalty * atom_edits
```

This detached search-ranking cost alone uses probability floor `1e-12`,
declared as `probability_floor_in_detached_cost_only`; differentiable NLL and
local/cut/nonempty risks remain unfloored. A valid witness must pass connected native sanitization and canonical
shared-schema roundtrip checks. Best observed valid witness is preferred to
any partial target; no global minimum or nearest-valid distance is proved.

Atom substitutions remain disabled by default. If enabled, they change only
occupied atom labels, with fixed formal charges and occupied-slot identity;
the default permits one changed atom and the prototype can explicitly allow
two. Such a substitution can guide the full NLL only after a complete valid
witness is independently rechecked. Partial targets never change atom labels.
The additional cost reduces an inexpensive high-valence shortcut but does not
eliminate it or establish preserved composition/sulfur behavior.

If no valid witness is found, a partial target requires Pareto improvement in
native observed diagnostic categories: no category worsens and at least one
improves, including extra connected components. It remains explicitly invalid
and atom-preserving. An unchanged graph is not a partial target. Diagnostic
counts are not calibrated chemical distances, and a partial target is never
substituted for the current shared molecule consumed by a scorer.

## Loss routing and gradient scope

`failure_aware_repair_loss(decoded, prepared, spec, config=...)` returns the
original full-valid NLL and separate experimental components. A newly found
complete valid witness **replaces** local/cut/nonempty fallback on that row;
it does not receive contradictory penalties using the original atom's cap.
Partial and no-witness rows retain the fallback signals. The returned receipt
distinguishes `failed_rows` from actual `fallback_rows`.

| Output component | Applies to | Direct gradient |
| --- | --- | --- |
| `valid_full_nll` | Original accepted valid targets, unchanged | Full atom/occupied-charge/unordered-bond categorical NLL |
| `extra_valid_nll` | Complete valid witness from the extra pass | Full categorical NLL, including an explicitly enabled valid atom substitution |
| `partial_edited_nll` | Explicit invalid Pareto-improving partial witness | Changed unordered bond labels only |
| `local_bond_risk` | Failed rows without a complete valid witness; supported hard occupied atoms | Bond logits only; atom/charge/occupancy references and caps are fixed |
| `component_cut_risk` | Those fallback rows with multiple original components | Bond logits across frozen component cuts |
| `nonempty_risk` | Empty fallback rows | Atom logits through probability of at least one non-`NO_ATOM` slot |

The new local term is negative log probability that summed incident bond order
does not exceed a cap selected from the fixed hard atom/charge identity. A
log-space convolution computes that local event under the categorical bond
law. It is **not** the historical probability-weighted expected-excess loss,
and soft atom probabilities do not directly enlarge the cap. Only the upper
bound is represented: undercoordination is allowed for implicit hydrogens,
and aromatic bonds count optimistically as order 1. This is not the probability
of a native-valid molecule or of an exact allowed valence/aromatic state.

Component-cut risk penalizes absence of every cross-component edge for each
frozen component. Satisfying these local cut events does not establish global
connectivity or a chemically permissible connecting bond. The nonempty event
uses a stable log-space first-present decomposition rather than subtracting
a near-one empty probability.

No probability floor manufactures a differentiable gradient. Unsupported local identities,
Kekulization/aromaticity, radicals and other global defects remain incompletely
covered. Some failed rows can still have zero or unhelpful gradient: the
prototype does not promise nonzero guidance for every failed graph, recovery
of every molecule or chemical validity. Shared network/latent updates can
indirectly alter atom identities and composition even when a local term has
no direct atom-head gradient. Optional atom-edit targets add another possible
route to high-valence elements such as sulfur; empirical retention checks
remain necessary before any adoption.

## Normalization, coefficients and identity

Every component retains the all-scheduled-row denominator, including rows
without a contribution. Complete-witness NLL first averages over
`N + K + K*(K-1)/2` categorical decisions. Partial NLL first averages only the
changed unordered bond labels, so its scale is deliberately different and
must not be presented as equivalent to full NLL. Local risk sums supported
atom risks divided by all hard occupied atoms; cut risk averages original
component cuts; nonempty risk contributes one negative-log event per empty
row. The preparation receipt records these exact normalizations.

`FailureGuidanceConfig(version="repair-failure-guidance-v1")` has experimental
defaults `extra_valid_weight=1`, `partial_weight=1` and
`local_bond_weight=component_cut_weight=nonempty_weight=0.1`. These are
uncalibrated research coefficients, not native-validated settings. The local,
cut and nonempty weights must be positive; extra-valid/partial weights may be
nonnegative. The total adds these weighted components to the original valid
NLL. This per-batch API does not automatically apply real/prior branch means,
the outer repair coefficient, population-JS mixture weights or an epoch plan.
Any later training integration must explicitly preserve or version those
choices rather than silently changing source121's 0.25/0.75 means or 1:2 protocol.

Preparation identity binds schema, candidate IDs, full verified original target
records/labels, original receipt, frozen failure references, witness identities
and coverage metadata. Every forward rechecks that binding. Freeze preparation
across the declared loss/step comparisons; refresh explicitly from the next
original teacher snapshot. Chemistry checks and search remain detached. The
API returns evidence but does not itself persist a campaign, submit jobs or
install automatic continuation/report hooks.

## Explicit opt-in API

This illustrative call sequence is not executed by the active trainer:

```python
from latentmol.repair_progress import ProgressSearchConfig
from latentmol.repair_failure_guidance import (
    FailureGuidanceConfig,
    prepare_failure_guidance,
    failure_aware_repair_loss,
)

# decoded must be the exact snapshot used by this original teacher call.
base = teacher.build_targets(decoded, candidate_ids=candidate_ids, update=update)
prepared = prepare_failure_guidance(
    decoded, base, spec,
    progress_search=ProgressSearchConfig(allow_atom_edits=False),
)
terms = failure_aware_repair_loss(
    decoded, prepared, spec, config=FailureGuidanceConfig(),
)
```

Use `progress_search=None` to opt into the declared fallback loss without the
additional search. Atom substitutions require a separate explicit
`ProgressSearchConfig(allow_atom_edits=True, max_atom_edits=1,
atom_edit_penalty=3.0)`. Choosing that option is a new target policy; it does
not modify the running campaign or permit independent scorer identities.

## Validation pending and adoption boundary

Modularity review passed and standard-library AST parsing passed for the two
prototype modules and `tests/test_repair_failure_guidance.py`, with no project
imports or numerical execution. Fixtures now include a true four-edit-depth
case, all-attempt normalization, original NLL parity, valid-witness replacement
and provenance rejection; they have **not been executed**. Eight active
source121 scientific files remain byte-identical, and no package or job was
submitted for this prototype. One metadata-only
HPC access attempt was rejected with `Permission denied`; no repeated attempt,
submission or active-job change followed. Access failure is not a scientific
gate result. Historical source121 native passes and source122 optimizer
fixtures do not validate these new losses or search settings.

Before adoption, allocated tests need to establish original accepted-target
NLL parity, normalization/provenance rejection, bounded deeper-than-three-edit
coverage, optional atom/charge/occupied-slot constraints, valid versus partial
routing, stable finite gradients and honest unsupported/zero-gradient cases.
Native benchmarks must measure actual added search/update/epoch wall time,
memory, coverage and composition/sulfur/reconstruction/validity retention from
authenticated checkpoints. Existing selected epoch timings do not transfer
to this extra objective. Any later campaign needs its own immutable source,
configuration, objective declaration and actual readiness/submission receipts;
no scientific or quota/runtime gate is waived by this prototype.
