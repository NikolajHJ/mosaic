# Retiring DBMol exploratory into Mosaic

**Draft for the team · November 25, 2026.** Make the NikolajHJ Mosaic fork the home for VAE training, evaluation and use in molecular design. The proposed handoff is the first durable checkpoint **at the end of the current attention leg** that can be resumed successfully from Mosaic. This is a plan for a future change. The existing allocation, callbacks and checkpoints remain under their current owner during preparation.

## Sequence and decision points

1. **While this leg waits or runs, inventory the exact source and assets.** Build a manifest for tracked, modified, deleted, untracked and required ignored paths. Compare it to the sealed source actually submitted and record later local edits separately. Classify entries as maintained in Mosaic, already present there, external artifact, or archive. Back up Git refs, the working tree including untracked code, and irreplaceable outputs with hashes and a restore check. Do a dry run of the import on an isolated branch in the destination. These are future preparation steps.
2. **At the allocation boundary, pin the actual producer output.** Record scheduler outcome, terminal update and epoch cursor, architecture, checkpoint SHA-256 and size, effective recipe, sealed source and quality panel. Copy or pin the artifact before rolling retention can prune it. If the job never dispatches or ends without a usable expanded checkpoint, keep DBMol as training owner and recover from the last verified state. The original parent at 631116 is a recovery point for the older architecture.
3. **Reproduce the resume path under Mosaic.** Restore the already-expanded architecture directly. The current entry unconditionally applies the 4,526,158 → 5,058,652 graft. Replaying it on the successor would apply the wrong transition. The current reader also binds a receipt to a resolved checkpoint path. Preserve the old checksum-verified receipts and create a new location manifest pointing back to them. Keep reads of the completed epoch-47 parent (575498), frozen epoch-46 teacher (325498), and the 60M data manifest intact. Bundle the launcher and reference or package the hash-pinned CUDA resolver explicitly. The current job calls a launcher in a *previous* DBMol release. [Resume entry](../experiments/vae/attention_next_leg.py) · [Resume reader](../src/latentmol/training/projected_continuation.py) · [Checkpoint publication](../src/latentmol/training/combined_continuation.py) · [HPC wrapper](../experiments/vae/run_checkpoint_comparison.sh)
4. **Run one disposable resume comparison.** From the same saved bytes and fixed inputs, compare architecture/parameter shapes, enabled losses, held-out hard graphs, prior occupancy and bond logits, and the latent gradient of the same scalar. Record numeric differences and tolerances for the dtype and device. Check the next real row IDs, prior RNG draws, AdamW state and parameter ordering. Take one scratch update, save, and reload with the Mosaic entry. Verify the next cursor and finite loss/gradients, with frozen teachers untouched. Use a separate output directory. The old checkpoint and split are the reference. [Resume regression](../tests/training/test_projected_resume.py) · [Attention tests](../tests/training/test_attention_expansion.py) · [Ordering tests](../tests/datasets/test_ordering.py)
5. **Hand production to one scheduler owner.** Reconcile the old worker, all dependent callbacks and their receipts before making a successor eligible. A completed worker can already have a queued child. If that happened, choose a later clean handoff or explicitly coordinate replacing just the pending successor. Submit one Mosaic leg into a new output root; record the old and new job IDs and parent hash. Confirm its first quality panel and first durable expanded checkpoint can be reloaded. Preserve the old launch path as recovery until this succeeds. If the smoke or first save fails, stop the Mosaic handoff and use a single verified producer to recover.
6. **Retire the source only after restore is demonstrated.** From a clean Mosaic checkout, run the trainer smoke, load both inference exports if a new one was published, and render one historical report from saved outputs. Verify the archive and source-to-destination index restore a representative old result including its evidence links. Refresh the inventory of remaining job consumers, add a read-only retirement pointer in DBMol, and direct new development to Mosaic. Deletion of an old checkout, remote or HPC tree is a separate decision after backup verification.

**The first deliverable after this plan** would be the migration manifest and an isolated Mosaic import branch. The first production milestone would be a Mosaic-launched leg resuming from the terminal checkpoint of the wider-attention model with its original next data row. Those are separate from choosing whether the new attention improves molecular quality.
