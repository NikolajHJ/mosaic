## 17 November: projection recovery reruns

Question: can a more robust valence projection complete the five partial
500-update runs, and what is the matched weight-0.5 versus projection-only
result when both use the same correction? The first dual solve remains the same.
If it misses KKT tolerances, the operator restarts L-BFGS-B from that solution,
then tries SLSQP if needed; it retains the candidate with the smallest normalized
KKT residual. Any remaining finite KKT violation is recorded as `kkt_warning`
and its magnitude is retained in the operator log, rather than stopping a
bounded exploratory run. Nonfinite outputs still stop. This is a numerical
method change and the reruns must be identified separately in comparisons.

Three CPU tests covered retry feasibility, unresolved-warning recording and
nonfinite rejection. Five last-saved prior states also passed finite/simplex
checks; these were not necessarily the precise failing solver inputs. Native
correctness and the actual failed cases remain to be checked through the runs.

submitted separately to V100, jobs 30099723–30099728, 500 updates each, LR 60

## 18 November: projection recovery results

All six reruns completed 500 updates with frozen checks passing. Five found a
new valid connected molecule during optimization; the sparse-only fragmented
control found none. None of the six ended with a valid connected argmax.

For the rerun fragmented seed-17 pair, the projection-only control's best valid
hard contact score was 0.28018 (update 2); the weight-0.5 DeFoG arm reached
0.33080 (update 208). Both final molecules were disconnected. This is one paired
comparison; it does not measure binding affinity.

The earlier weight-0.5 attempt with the same seed reached 0.46203 and ended
valid. Its trajectory and the rerun diverged despite identical initial graph,
runtime versions and V100 model. The old control used a different V100 subtype
from its rerun. The change in outcome shows sensitivity to execution; its cause
is not established. Avoid treating the earlier and new attempts as interchangeable
or interpreting them as independent seeds.

Operator records contain no triggered solver retries or KKT warnings in these
six executions. They therefore show that these trajectories finished without
the earlier stops, but do not establish that the fallback resolves the exact
inputs which caused those stops; the CPU test exercised a simulated failure.
