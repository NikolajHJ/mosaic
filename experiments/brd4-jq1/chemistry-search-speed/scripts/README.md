# Experimental speed tools

Separate exact reuse/cost and deterministic parallel search adapters, benchmark,
immutable packager and allocated launcher. These are not installed into current
scientific runs. See the experiment protocol and dated run record.

`round2_*` tools isolate the central-cache/parallel comparison and a separately
admitted real-GPU matrix-loss benchmark. `gpu_matrix.py` supplies telemetry and
mathematically equivalent local-risk candidates; it cannot certify native
chemistry validity. `profile_oracle.py` times unchanged CPU native calls.

`gpu_adoption*` owns the separate immutable scheduler-lag admission correction,
its one-shot staging/fresh-admission callers, compact read-only collector and
independent byte/XML/LSF verifier. It adopts the original CPU benchmark and
submits the unchanged source02 GPU command only after actual new metadata-CPU
completion and full capacity checks. Never replay its recorded submissions.
`round2_verify.py` independently checks original source02 evidence locally
using standard-library byte, XML and schema checks only.

`full_model_*` owns separate unchanged-setting baseline/combined full-model
pilots, policy contracts and immutable orchestration. `gpu_local_bridge.py` and
`gpu_local_worker.py` retain Boltz's CPU JAX optimizer and CUDA native-model
worker while offloading only local-risk value/gradient arithmetic. The bridge
never reuses probability-dependent results and cannot replace native validity.

`gpu_process_admission.py` distinguishes whole-job GPU exclusivity from NVIDIA
compute-mode exclusivity for Boltz's two CUDA processes. It requires actual
resolved LSF `mode=shared:j_exclusive=yes:mps=no`, one selected L40S in Default
compute mode, and a bounded real Torch/JAX coexistence canary before the original
native-model checks. It changes no GPU mode, scientific arithmetic or optimizer
settings. The canary has no model weights and is not native readiness. Production
and speed claims still require the complete allocated original checks and pilots.

`production_*` owns the separate prospective adoption/serial production controller. It binds Pro03 and Bol02 independently, retains original native and terminal checks plus stride20 persistence, and admits both full chemistry forecasts before any long job. Existing/unknown outcomes cannot be replayed. `production_prepare.py` is local stdlib packaging; `production_launch.py` is its one-shot authenticated stage and allocated CPU/callback entry.

`report_retirement.py` is a separate, explicit byte/metadata-only offload operator.
After review, run it once with `--execute` from this checkout. It pins the exact
81-file plan under `results/hpc/20261025-chemistry-report-retirement-01`, rehashes
all three complete laptop backups and all 78 regular report members before its
single SSH attempt, and refuses an existing local execution or remote operation.
It checks actual inactive producer/job/process evidence, nine sealed source
inventories and the unchanged original input/proof closure before removing only
matching, singly linked regular copies. It retains changed/absent/linked files,
removes no directories, and preserves local historical viewers and native runs.
Each exact unlink has a durable intent/result; all raw audit bytes are returned
and independently reconciled locally. The final unchanged whole storage guard
has a fresh parent and may still fail; maximum candidate logical bytes are
571,264,343, not a promise of production capacity. An interrupted or unknown
outcome must be inspected from its existing operation, never replayed.
